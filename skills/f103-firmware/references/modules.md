## 缺 HAL 例程、需自行移植的模块

**SG90 舵机**：C8 核心板目录只有标准库版本；HAL 版在别的板型下且引脚不同。按扩展板引脚自行实现：
`PB0 = TIM3_CH3`，`PSC = 71 / ARR = 19999`（1 MHz 计数、50 Hz、1 µs 分辨率）。

**RD03 雷达**：C8 核心板只有标准库版本，移植时：

1. 串口层改写为 HAL，但保留原 API 名称，使厂商的解析代码可以直接复用
2. 中断里按 `\n` 置标志，主循环消费后复位缓冲
3. 引脚冲突见下表：USART3 的 PB10/PB11 与排针上的 OLED 软 I2C 相同

## 组合使用时的资源分配

| 资源 | 分配方式 | 原因 |
| --- | --- | --- |
| TIM3 | 只给舵机 PWM（CH3/PB0） | 编码器若占用 TIM3 的编码器模式，会破坏 50 Hz PWM |
| 编码器 | 用另一个定时器（TIM2）1 kHz 中断软件解码 | 人手转动频率远低于 1 kHz，够用且不占硬件编码器 |
| I2C | 软件 I2C，引脚运行时可配 | 需要适配专用座与排针两套接法 |
| 蜂鸣器 | 4 kHz 方波而非直流高电平 | 该模块按无源特性驱动才发声 |

## 软件 I2C 在 F1 上的实现约束

开漏输出模式不会启用内部上拉。释放总线时必须切到 `GPIO_MODE_INPUT + GPIO_PULLUP`，否则总线悬空、读到的"低"被误判为 ACK，扫描时每个地址都"应答"，屏幕表现为初始化成功却全黑。

兜底判据：一次扫描中 ACK 数超过 8 个即判定扫描器失效，先修时序再继续。

## 已知引脚冲突

| 引脚 | 争用者 |
| --- | --- |
| PA4 | 光敏 AO、热敏 AO、循迹 AO、雨量 AO、W25Q64 CS、SPI1 |
| PA5 | 光敏 DO、热敏 DO、循迹 DO、土壤 AO、SPI1_SCK |
| PA6 / PA7 | 编码器 A/B、SPI1_MISO/MOSI |
| PB10 / PB11 | USART3（雷达）、排针 OLED 软 I2C |

组合使用时按"一次只改一处"的原则改 `bsp_*.h` 的宏，并同步对应的 GPIO 时钟使能。
