# F103C8T6 引脚与模块接线

数据来源分三级，引用时带上级别：

- **A｜例程源码**：从野火 HAL 例程的 `bsp_*.h` 宏读出（GBK 解码）
- **B｜原理图**：从 `f103_doc` 的扩展板/核心板原理图 PDF 渲染后读出；与 A 冲突时以 A 为准
- **C｜推断**：未逐条核对，使用前先验证

## 芯片与时钟（A）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 型号 | STM32F103C8T6（Cortex-M3） | 核心板丝印 / 例程 |
| Flash / RAM | 64 KiB / 20 KiB | `test.sct` 的 `0x10000` / `0x5000` |
| 外部晶振 | 8 MHz HSE | `RCC_PLL_MUL9` → 72 MHz |

部分国产板标注 C8T6 实为 128 KiB 或非 ST 芯片，烧录前先读容量，见[烧录与调试](flash-debug.md)。

## 例程通用引脚（A）

| 功能 | 引脚 | 说明 |
| --- | --- | --- |
| USART1_TX / RX | PA9 / PA10 | 115200 8N1，printf 重定向目标 |
| USART3_TX / RX | PB10 / PB11 | 雷达等串口模块 |
| LED1 红 / LED2 绿 / LED3 蓝 | PA1 / PA2 / PA3 | 低电平点亮（3V3→LED→1 kΩ→引脚） |
| LED4 | — | 电源指示，常亮 |

## SWD 调试口（A+B）

核心板 `J2` 为 1×5 排针：

| 针号 | 信号 | 接到 DAP |
| --- | --- | --- |
| 1 | 3V3 | 不接 |
| 2 | NRST | RST |
| 3 | PA14 / SWCLK | CLK |
| 4 | PA13 / SWDIO | DIO |
| 5 | GND | GND |

`fireDAP_Little` 只出 SWD，针序为 `RST / CLK / GND / DIO / 3V3`，因此实际接 4 根，3V3 空置。该探针不给目标板供电，核心板需另用 Type-C 供电。

BOOT 跳线 `J5`（2×5）：不插跳线时 BOOT0 由 10 kΩ 下拉，从用户闪存启动，正常调试无需改动。

## 引脚冲突（组合使用前必读）

各模块例程彼此独立，默认会重复占用同组引脚：

| 引脚 | 争用者 |
| --- | --- |
| PA4 | 光敏 AO、热敏 AO、循迹 AO、雨量 AO、W25Q64 CS、SPI1 |
| PA5 | 光敏 DO、热敏 DO、循迹 DO、土壤 AO、SPI1_SCK |
| PA6 / PA7 | 编码器 A/B、SPI1_MISO/MOSI |
| PA9 / PA10 | USART1 调试串口，建议保留 |
| PB10 / PB11 | 排针 OLED 软 I2C 与 USART3（雷达），不可同时使用 |

改引脚时只改 `bsp_*.h` 的宏并同步 GPIO 时钟使能，不要照搬另一模块的初始化函数。

## OLED 的两套接法与总线判据

| 接法 | SCL | SDA | 总线状态 |
| --- | --- | --- | --- |
| 扩展板 OLED 专用座 | PB6 | PB7 | 板载上拉，扫描只应答 0x78 |
| 核心板排针 / 通信接口2 | PB10 | PB11 | 无 I2C 上拉，扫描会出现大量假 ACK |

换插座必须同步改驱动里的引脚宏与 SDA 读回逻辑。

### 软件 I2C 的必备写法

STM32F1 的开漏输出模式（CNF=01）**不启用内部上拉**，释放时是真正的高阻。总线无外部上拉时 SDA 读到随机电平，每个地址都被判为 ACK，表现为初始化成功但屏幕全黑。

```c
/* 释放：切成输入 + 内部上拉 */
GPIO_MODE_INPUT, GPIO_PULLUP
/* 拉低：开漏输出 + 写 0 */
GPIO_MODE_OUTPUT_OD, 0
```

兜底判据：一次扫描 ACK 数 > 8 即判定总线悬空或 SDA 被拉死，先修时序再初始化。

**电平探测不能替代总线探测**：内部下拉/上拉读到的固定电平只反映外部电阻网络，不能证明器件在那儿。要确认器件存在，必须做真实的事务并读 ACK。
